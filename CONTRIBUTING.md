\# Guía de Contribución



\## Flujo de trabajo



1\. Crear una rama desde `main`.

2\. Realizar cambios según el módulo asignado.

3\. Hacer commits claros.

4\. Subir la rama al repositorio remoto.

5\. Crear un Pull Request hacia `main`.

6\. Revisar cambios antes de fusionar.

7\. Resolver conflictos si aparecen.



\## Convención de ramas



\- `feature/nombre-modulo`

\- `docs/nombre-documentacion`

\- `fix/nombre-error`

\- `chore/nombre-tarea`



\## Convención de commits



\- `feat:` nueva funcionalidad.

\- `fix:` corrección de errores.

\- `docs:` documentación.

\- `chore:` mantenimiento o configuración.

\- `ci:` automatización.



\## Pull Requests



Cada Pull Request debe incluir:



\- Cambios realizados.

\- Pruebas realizadas.

\- Checklist de revisión.



\## Resolución de conflictos



Si ocurre un conflicto, se debe:



1\. Revisar el archivo afectado.

2\. Eliminar los marcadores `<<<<<<<`, `=======`, `>>>>>>>`.

3\. Conservar la versión correcta o combinar cambios.

4\. Ejecutar pruebas.

5\. Hacer commit de la solución.
